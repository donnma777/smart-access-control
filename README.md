
# 🔒 Smart Access Control（高度なアクセス制御プラグイン）

  

このWordPressプラグインは、クローラー・User-Agent・IPアドレスを組み合わせて、アクセスを精密に制御する管理者向けプラグインです。

投稿・固定ページ単位で制御を有効化でき、検索エンジン、AIクローラー、スクレイピングツール、不正または偽装されたブラウザアクセスを柔軟に制御できます。

デフォルトではすべてのアクセスを許可しつつ、ALL拒否（ホワイトリスト）モードを利用することで、許可したクローラーのみを通す厳格な運用も可能です。

  

AIの学習・データ収集を目的としたクローラーや、User-Agent を偽装するアクセスを制限したいサイト運営者・管理者に最適です。

  

## 🌟 主な機能

- ページ単位のアクセス制御

- 投稿・固定ページごとにアクセス制御を有効化できます。 ALL拒否 / 個別拒否モード 個別拒否（ブラックリスト）：選択したクローラーを拒否

- ALL拒否（ホワイトリスト）：選択したクローラーのみ許可 不正・偽装ブラウザ（User-Agent）制御 Headless

- Chrome、Selenium、UA空アクセス、古いブラウザなど、不正アクセスの可能性が高いUAを検知・遮断します。

- グローバル設定とページ固有設定の両方に対応しています。

- 網羅的なクローラー定義

- Google、Bing、主要AI/LLM系（Gemini、GPTBot、ClaudeBot、GrokBotなど）、SNSプレビュー、SEOツール系を含む多数のクローラー定義を標準搭載。

- 定義は管理画面から自由に編集可能です。

- IPアドレス範囲制御と自動更新

- User-Agent を偽装したアクセスに対し、IPアドレス範囲で制御できます（ALL拒否モード時）。

- Googlebot・GPTBot の公式IPリストは、毎時／1日2回／毎日／毎週／月1回などのスケジュールで自動更新できます。

- グローバルデフォルト設定

- ページ編集画面での制御スイッチの初期状態（ON/OFF）を設定できます。

- API / JSON リクエスト対応

- REST API などの JSON リクエストを自動判別し、適切な 403 JSON レスポンスを返します。

  

## ⚠️ 重要な注意点（必ずお読みください）

  
**本プラグインでトラブルが起きても一切責任を負いません。**

二次配布はお断りしています。

### robots.txt・サーバー設定が優先されます

本プラグインは **WordPress（PHP）レイヤーで動作**します。

そのため、以下の設定が存在する場合、**本プラグインの制御よりも先に処理されます**。

-  `robots.txt` によるクロール制御

- Webサーバー設定（Apache / Nginx）

- WAF・CDN（Cloudflare 等）のブロックルール

- OS / Firewall レベルでの制限

  

👉 **robots.txt やサーバー側で拒否されているアクセスは、本プラグインでは制御できません。**


---

### PHP に到達しないアクセスは制御できません

以下のような場合、本プラグインは動作しません。
  
- クローラーやボットが **PHP実行前に遮断**されている場合

- サーバー設定で `php.ini` / FastCGI / FPM による制限がある場合

- 特定の User-Agent / IP が Web サーバー側で拒否されている場合

👉 **WordPress（PHP）が実行されることが前提条件**です。

---

### クローラーが許可されていないと動作しないケース

- サーバー側でクローラー自体が拒否されている

- WAF や CDN で User-Agent / IP が未許可

- JSON / REST API がサーバー側で制限されている

  

このような場合、

**本プラグインで「許可」設定をしていてもアクセスされません。**

  

---

  

### 推奨構成

  

- robots.txt：**最小限**

- クローラー制御：**本プラグイン**

- 大規模防御：**WAF / CDN**

  

👉 本プラグインは **「最終判断レイヤー」** として使うのが最適です。

  

### 画像・静的ファイルは制御対象外です

  

本プラグインは **WordPress（PHP）が処理するリクエストのみ** を対象としています。

  

そのため、以下のような **画像・静的ファイルへの直接アクセスは制御されません**。

  

- 画像ファイル（jpg / png / gif / webp / svg など）

- CSS / JavaScript ファイル

- PDF / ZIP などのダウンロードファイル

-  `/wp-content/uploads/` 配下への直接アクセス

  

これらのリクエストは **Webサーバー（Apache / Nginx）や CDN が直接処理**するため、

本プラグインの制御ロジックは実行されません。

  

---

  

### 画像・静的ファイルを制御したい場合

  

画像や静的ファイルへのアクセスを制御したい場合は、以下の方法をご検討ください。

  

-  `.htaccess` / Nginx 設定による制御

- CDN（Cloudflare 等）のルール設定

- WAF（Web Application Firewall）

- サーバー側の IP / User-Agent 制限

  

👉 **本プラグインは「HTML / API レスポンス制御」に特化しています。**

  
  
  

## ⚠️ 重要な免責事項 (保証の限界)

  

**インストール前にバックアップをお取りください。本プラグインで環境が破損しても一切責任を負いません。**

  

このプラグインは、既知の主要なクローラーのUser-Agent (UA) 文字列を厳密にチェックし、アクセスをブロックします。

しかし、**完全にクローラーのアクセスを防ぐ保証はありません。**

* クローラーは常に新しいUAを使用したり、既存のUAを偽装したりする可能性があります。

* アクセスログ上では通常のブラウザ（Human User）として見せかける高度なスクレイピングツールが存在します。

* 本プラグインの制御ロジックを回避する、未知のアクセス方法が出現する可能性もあります。

本プラグインは、**アクセス制御の労力を最小限に抑え、既知の主要なボットを効果的にブロックする**ことを目的としています。完全な防御が必要な場合は、サーバーレベルでの追加の対策（WAFなど）をご検討ください。

  

## 🤖 主要プラットフォームのクローラー区分について

  

本プラグインでは、Google・Microsoft・Amazon などの公式ドキュメントに基づき、

クローラーを以下のように分類して管理できます。

  

### Google クローラー

- 一般検索クローラー（Googlebot など）

- 特殊用途クローラー（AdsBot など）

- ユーザートリガーフェッチャー（Site Verification 等）

  

### Microsoft / Bing

- bingbot（検索）

- adidxbot（広告）

- BingPreview（リンクプレビュー）

  

### Amazon / AWS

- Amazonbot（検索・AI用途）

  
  

## 🚀 インストール方法

  

1. プラグインフォルダ（例: `grok-crawler-control`）全体をZIPファイルに圧縮します。

2. WordPress管理画面の **プラグイン** > **新規追加** へ移動します。

3. 上部にある **プラグインのアップロード** ボタンをクリックし、作成したZIPファイルを選択してインストールします。

4. プラグインを有効化します。

  
  

# 💡 使用方法

  

## まず理解すること（30秒）

  

このプラグインは **「ページ単位で ON にしたときだけ」** アクセス制御が有効になります。

  

- 何も設定しなければ **全アクセス許可**

- 記事ごとに **制御ON** にすると、そのページだけ厳密な制御が有効

  

👉 **最初から全ページをブロックすることはありません**

  

---

  

## STEP 1️⃣ # アクセス制御 設定（最初に1回だけ）

  

**管理画面 → 設定 → アクセス制御 設定**

  

ここでは「共通ルール」を決めます。

定義キーは必須です。

  

### ① User-Agent 定義（クローラー一覧）

  

- Google / Bing / AIクローラー / SNS / SEOツールなどが初期登録済み

- ここで定義したクローラーが、記事編集画面で選択可能になります

- 自由に追加・編集・削除できます

  

👉 **ここは「辞書」**（まだブロックはされません）

  

---

### ② IPアドレス範囲（任意・推奨）

  

- Googlebot / GPTBot の **公式IP範囲を自動更新**できます

- 更新頻度：毎時 / 半日 / 毎日 / 毎週 / 月1回 など

  

👉 **User-Agent 偽装対策（重要）**

  

---

  

### ③ 不正UAパターン（推奨）

  

- Headless Chrome

- Selenium / Puppeteer

- curl / wget / 古い偽装UA など

  

👉 **ここで設定したUAは、制御ONページで自動的にブロック対象になります**

  

---

  

### ④ ページ個別制御の初期状態（任意）

  

- 新規投稿時に制御を **ON / OFF どちらにするか**

- 初心者は **OFF推奨**

  

---

  

## STEP 2️⃣ 記事・固定ページで制御を有効化

  

**投稿 / 固定ページの編集画面**

  

### ①「クローラー制御を有効にする」にチェック

  

👉 **ここで初めて制御が有効になります**

  

---

  

### ② 制御モードを選択（重要）

  

#### 🔹 個別拒否（ブラックリスト）【推奨・安全】

  

- チェックしたクローラー **だけを拒否**

- それ以外はすべて許可

  

**こんな場合におすすめ**

- 検索流入を維持したい

- AIクローラーだけ止めたい

- 初めて使う場合

---

#### 🔹 ALL拒否（ホワイトリスト）【上級者向け】



- チェックしたクローラー **だけを許可**

- それ以外はすべて拒否

⚠ **Googlebot 等を許可しないと検索結果から消えます**

---

### ③ User-Agent（クローラー）を選択

- 選択内容は **制御モードに応じて意味が変わります**

  
| 制御モード |チェックしたクローラー  |
|--|--|
| ブラックリスト  | 拒否対象  |
| ホワイトリスト  | 許可対象  |

---

  

### ④ IPアドレス範囲制御（ALL拒否時のみ）

  

- User-Agent を偽装したアクセスを防ぐための追加防御

- 許可するクローラーの **IP範囲も必ずチェック**

  

👉 **ホワイトリスト運用では必須**

  

---

  

### ⑤ ページ固有の不正UAパターン（任意）

  

- グローバル設定に加えて

-  **このページだけ**追加でブロックしたいUAを指定

---

## STEP 3️⃣ 保存して完了


- 通常のブラウザアクセスは影響を受けません

- 対象外のページには一切影響しません

---

## 🚦 よくあるおすすめ構成

### ✔ AIクローラーだけ止めたい

- 制御ON

- 個別拒否（ブラックリスト）

- GPTBot / ClaudeBot / Gemini などをチェック

---

### ✔ 検索エンジン以外をすべて拒否したい

- 制御ON

- ALL拒否（ホワイトリスト）

- Googlebot / Bingbot を許可

- IPアドレス範囲も必ず許可

---

### ✔ API / JSON リクエストを正しく返したい

- プラグインが自動判別

- 403時も **JSONレスポンス**を返します（追加設定不要）

---

## ⚠️ トラブルを避けるために

- 初回は **ブラックリストモード**で試す

- ALL拒否は **検索流入確認後**に使用

- 不安な場合は **ステージング環境推奨**

---

- robots.txt では不可能な **ページ単位制御**

- AI / LLM クローラーの厳密な選別

- UA偽装 + IPチェックによる二段防御
